# 용역별 Project GPT 분석 운영 가이드

작성 기준일: 2026-05-06
대상: 삼우씨엠 전략사업그룹 CM 용역 제안 담당자
목적: ChatGPT를 처음 사용하는 담당자도 용역별 Project를 만들고, GPT 3개를 활용해 RFP 분석, 제안서 Review, 발표 Q&A를 수행할 수 있도록 안내한다.

---

## 1. 이 가이드의 결론

용역별 Project에서는 다음 방식으로 운영한다.

```text
Project 소스 = 팀 공용 보관함
채팅 첨부 = 실제 GPT가 읽고 분석할 작업 파일
부서 공용 GPT = 분석 기준과 결과물 형식을 잡아주는 전문가
```

현재 운영상 Project 소스에 있는 PDF를 Custom GPT가 항상 안정적으로 읽지 못할 수 있다. 따라서 실무에서는 다음 원칙을 적용한다.

```text
원문 판단이 필요한 채팅에는 필요한 PDF를 채팅에 직접 다시 첨부한다.
Project 소스에는 기준 파일과 최종 산출물을 보관한다.
```

## 3. GPT 기능 설정 권장값

`.docx` 결과물을 받고 싶다면 GPT 생성 시 `Code Interpreter & Data Analysis` 또는 파일 생성 기능을 켜는 것이 좋다.

Word 결과물 파일명은 다운로드 오류를 방지하기 위해 반드시 영문 소문자, 숫자, `_`만 사용한다. 문서 본문은 한글로 작성하되, 생성 파일명에는 한글, 공백, 괄호, 특수문자를 사용하지 않는다.

| GPT | 권장 모델 | 웹 검색 | 캔버스 | 이미지 생성 | Code Interpreter & Data Analysis | Actions |
|---|---|---:|---:|---:|---:|---:|
| 삼우CM RFP 분석 GPT | 최신 고성능 모델 | 선택 ON | ON | OFF | ON | OFF |
| 삼우CM 제안서 Review GPT | 최신 고성능 모델 | OFF | ON | OFF | ON | OFF |
| 삼우CM 발표 Q&A GPT | 최신 고성능 모델 | OFF | ON | OFF | ON | OFF |

### 설정 이유

- `웹 검색`: RFP 분석 GPT에서만 보조적으로 사용한다. RFP 판단은 업로드 원문이 우선이다.
- `캔버스`: 긴 보고서와 표를 다듬을 때 유용하다.
- `이미지 생성`: RFP 분석, Review, Q&A에는 필요하지 않으므로 끈다.
- `Code Interpreter & Data Analysis`: `.docx`, `.xlsx`, `.csv` 같은 파일 산출물을 만들 때 필요하다.
- `Actions`: 외부 API 연동 기능이므로 초기 운영에서는 사용하지 않는다.

## 4. 용역별 Project 생성 절차

### 4.1 Project 이름 규칙

권장 형식:

```text
YYMM_발주처_사업명_CM제안
```

예시:

```text
2605_발주처A_본관재건축_CM제안
2606_발주처B_복합개발_CM제안
2607_발주처C_업무시설신축_CM제안
```

### 4.2 Project Instructions 입력

Project를 만든 뒤 `Project Instructions`에 아래 파일 내용을 붙여 넣는다.

```text
ai_automation_package/project_templates/chatgpt_project_template_v3.md
```

주의:

- 이 파일은 Project 소스로만 올리는 것이 아니라, 내용을 복사해 Project Instructions에 붙여 넣어야 한다.
- Instructions는 Project 전체의 운영 기준이다.
- Project 소스는 파일 보관함에 가깝다.

## 6. 채팅별 파일 업로드 원칙

Project 소스에 파일을 올려도, 실제 분석 채팅에는 필요한 파일을 다시 첨부한다.

| 채팅 | 채팅에 직접 첨부할 파일 |
|---|---|
| 00_자료품질_OCR_확인 | 입찰공고문, RFP, 과업지시서, 평가기준 |
| 01_RFP_제안전략설계 | 입찰공고문, RFP, 과업지시서, 평가기준, 정정공고/Q&A |
| 02_제안서_통합Review | RFP, 과업지시서, 평가기준, 제안서 초안, 01_RFP_제안전략설계 결과 |
| 03_발표_QA_통합생성 | 평가기준, 최종 제안서, 발표자료, 01_RFP_제안전략설계 결과, 02_제안서_통합Review 결과 |
| 04_최종_PRM체크 | RFP, 평가기준, 최종 제안서, 최종 발표자료 |
| 05_사후평가 | 실제 심사 질문 기록, 발표 Q&A 결과 |

중요:

```text
RFP 원문 판단이 필요한 채팅에는 RFP PDF를 직접 첨부한다.
평가기준 판단이 필요한 채팅에는 평가기준 PDF를 직접 첨부한다.
제안서 검토가 필요한 채팅에는 제안서 초안 파일을 직접 첨부한다.
이전 결과물이 필요한 채팅에는 이전 결과물 파일을 함께 첨부한다.
```

## 7. 담당자가 실제로 따라 할 기본 절차

### 7.1 Project 생성 후 첫 작업

1. ChatGPT에서 새 Project를 만든다.
2. Project 이름을 규칙에 맞게 입력한다.
3. Project Instructions에 `chatgpt_project_template_v3.md` 내용을 붙여 넣는다.
4. Project 소스에 필수 원문과 output template을 올린다.
5. 새 채팅을 만든다.
6. 채팅명을 `00_자료품질_OCR_확인`으로 둔다.
7. 입찰공고문, RFP, 과업지시서, 평가기준을 채팅에 직접 첨부한다.
8. 아래 OCR 확인 프롬프트를 실행한다.

### 7.2 OCR 확인 프롬프트

```text
@삼우CM RFP 분석 GPT

이 채팅에 직접 첨부한 파일만 기준으로 자료 품질과 OCR 상태를 먼저 확인해줘.

절대 추정하지 말고, 실제로 읽을 수 있는 파일만 분석 가능으로 표시해줘.

아래 표로 작성해줘.
1. 파일명
2. 문서 유형
3. 첫 페이지 또는 목차 확인 가능 여부
4. 텍스트/OCR 품질
5. 표/배점 추출 가능 여부
6. 분석 가능 범위
7. 재업로드 또는 OCR 필요 여부

마지막에는 다음 중 하나로 판정해줘.
- 분석 가능
- 일부 분석 가능
- 분석 불가

분석 불가 파일이 있으면 이후 RFP 분석을 진행하지 말고 어떤 파일을 다시 올려야 하는지 알려줘.
```

완료 기준:

```text
RFP, 과업지시서, 평가기준이 모두 읽기 가능해야 다음 단계로 이동한다.
```

## 9. 01_RFP_제안전략설계

### 9.1 목적

`삼우CM RFP 분석 GPT`를 사용해 RFP 제안전략설계 관련 산출물을 한 번에 만든다.

포함 결과물:

1. 자료 품질/OCR 확인 요약
2. 필수조건/감점요소/제출조건
3. 평가기준 및 실제 의사결정 구조 분석
4. 발주자 문제 정의와 Hidden Needs
5. 핵심 리스크 구조화
6. Must-win 전략 및 Win Theme
7. 제안서 목차/페이지 구성
8. 기술지원 요청 Item / KOM 연계
9. 발표 예상 질문 Seed
10. 기술지원 업무협조 요청서 Word 초안
11. 분야별 기술지원 요청내용 요약 Word 초안

### 9.2 채팅에 직접 첨부할 파일

```text
입찰공고문.pdf
RFP_제안요청서.pdf
과업지시서.pdf
평가기준.pdf
정정공고_QA.pdf
rfp_analysis_table.md
kom_summary.md
technical_support_request.md
기술지원 업무협조 요청서_양식.docx
분야별 기술지원 요청내용 요약_양식.docx
```

### 9.3 통합 프롬프트

```text
@삼우CM RFP 분석 GPT

이 채팅에 직접 첨부한 입찰공고문, RFP/제안요청서, 과업지시서, 평가기준, 정정공고/Q&A를 기준으로 RFP 제안전략설계서를 작성해줘.

중요 원칙:
1. Project 소스가 아니라 이 채팅에 첨부한 파일을 우선 기준으로 삼아줘.
2. 파일을 실제로 읽을 수 없는 경우에는 분석하지 말고 "파일 확인 불가"로 표시해줘.
3. RFP 원문, 과업지시서, 평가기준의 판단은 추정하지 말고 근거 파일명을 표시해줘.
4. 불확실한 항목은 "확인 필요"로 표시해줘.
5. 결과는 Word 문서로 옮기기 쉬운 보고서 형식으로 작성해줘.
6. Word 결과물 파일명은 한글 없이 영문 소문자, 숫자, `_`만 사용해줘.
7. 첨부된 기술지원 Word 양식 2개는 참조 템플릿으로 사용하되, 생성 결과물 파일명은 반드시 영문으로 만들어줘.

아래 목차로 제안전략설계 결과물을 작성해줘.

# RFP 제안전략설계서

## 1. 자료 품질 및 OCR 확인 요약
- 파일별 읽기 가능 여부
- 표/배점 추출 가능 여부
- 분석 제한사항

## Executive Summary
- 사업명, 발주처, 용역명, 사업 위치, 주요 일정, 제출 조건
- 핵심 키워드 5~7개
- 수주 승부처 3개

## 2. Pass/Fail 조건 및 제출 리스크
- 제출조건, 감점, 실격, 블라인드, 발표조건
- 제안서 반영 위치와 미반영 리스크

## 3. 평가기준 및 의사결정 구조 분석
- 평가 항목 구조
- 배점 기반 중요도 또는 배점표 부재 시 역추론
- 평가위원 관점 핵심 평가 포인트
- 평가표와 실제 의사결정 기준의 괴리

## 4. 사업 추진 배경 및 발주자 문제 정의
- 정책적/시장적/조직적 배경
- As-Is / To-Be
- 실패 시 일정, 비용, 품질, 민원, 책임 리스크

## 5. Hidden Needs 분석
- Hidden Need
- 추론 근거
- 발주자 불안 또는 두려움
- 평가위원이 찾는 메시지
- 제안 대응 메시지

## 6. 프로젝트 핵심 이슈 및 리스크 구조화
- 입지, 규모, 공종, 이해관계자 기반 리스크
- 공정, 품질, 안전, 민원, 인허가, 원가, 계약 리스크
- 리스크 간 연계 구조

## 7. Must-win 전략 및 Win Theme
- Win Theme 3~5개
- 핵심 메시지 한 줄
- 대응 Hidden Need와 평가항목
- 일반적인 제안 vs 차별화 전략

## 8. 제안서 목차 및 페이지 구성
- 평가항목과 1:1 매핑되는 목차
- 권장 페이지 수
- 핵심 메시지, Evidence, 도식화 아이디어

## 9. 제안서 작성 가이드
- 절대 쓰면 안 되는 일반론 문장
- 평가위원이 선호하는 표현 방식
- 점수를 깎는 요소
## 10. 기술지원 요청 Item / KOM 연계
아래 표로 작성:
- 요청 분야
- 요청 Item
- 필요한 이유
- RFP/평가기준 근거
- 대응 Hidden Need 또는 Win Theme
- 제안서 반영 위치
- 필요한 산출물 형식
- 요청 담당자
- 요청 기한
- 우선순위

## 11. 발표 예상 질문 Seed
- 평가항목별 예상 질문 15개 이상
- Hidden Need 기반 압박 질문 10개 이상
- 답변 근거로 연결할 제안서 메시지

## 12. PM 확인 필요 사항
사람이 원문을 다시 확인해야 할 항목만 따로 정리해줘.

마지막으로 위 결과를 .docx 파일로 생성할 수 있으면 아래 3개 파일로 만들어줘.
- rfp_strategy_design_report.docx

```

해결:

```text
1부부터 작성해줘.
이어서 2부를 작성해줘.
마지막에 전체를 .docx로 묶어줘.
```

### 문제 4. `.docx` 파일을 만들지 못한다

해결:

```text
GPT 설정에서 Code Interpreter & Data Analysis 기능이 켜져 있는지 확인한다.
안 되면 Word에 붙여넣기 좋은 형식으로 다시 정리해달라고 요청한다.
```

### 문제 5. 분석 결과에 추정이 섞인다

해결:

프롬프트에 아래 문장을 추가한다.

```text
원문 근거가 없는 내용은 추정하지 말고 "확인 필요"로 표시해줘.
```
